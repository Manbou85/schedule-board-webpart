# SharePoint への登録と、ページへの追加(開発者向け)

リストの準備と WEBパーツの設定は `docs/LIST_SETUP.md` を見てください。

## 1. .sppkg を受け取る
- `.sppkg` は、WEBパーツをまとめた1つのファイルです(ファイル名 `schedule-board-webpart.sppkg`)
- いまは、Claude Code がチャットにファイルを添付して渡しています。ダウンロードして保存してください
- (将来)セキュリティクイズと同じように、GitHub の「Actions」で自動ビルドしてダウンロードする形にもできます

## 2. アプリカタログに登録する
アプリカタログとは、会社の SharePoint で使えるアプリ(WEBパーツなど)を置いておく場所です。

1. SharePoint 管理センターを開く
2. 左のメニューから「その他の機能」→「アプリ」の「開く」を選ぶ(表示がちがう場合は「アプリの管理」を探す)
3. 「アップロード」を押し、`.sppkg` を選ぶ
4. 確認画面が出たら「展開」を押す
   - 「このアプリをすべてのサイトで使えるようにする」にチェック → どのサイトでもすぐ使える
   - チェックしない → 使いたいサイトで「3.」が必要
5. 一覧に `schedule-board-webpart-client-side-solution` が出て、「有効」になっていれば完了

> 2回目以降(新しい版)は、同じファイル名でアップロードすると上書きされます。
> 「置き換えますか?」と聞かれたら「置換」を選び、もう一度「展開」を押してください。

## 3. (すべてのサイトにチェックしなかった場合のみ)サイトにアプリを追加する
1. テスト用サイト(本番は社内ポータル)を開く
2. 右上の歯車 ⚙ →「アプリの追加」
3. `schedule-board-webpart-client-side-solution` を選んで追加

## 4. ページに WEBパーツを置く
1. サイトで「+ 新規」→「ページ」を選び、新しいページを作る(すでにあるページでもよい)
2. **セクションのレイアウトは「1列」または「全幅の列」**にする(週間表示は横に広いため)
3. ページの中の「+」(WEBパーツを追加)を押し、検索欄に「行動予定」と入力して「行動予定表」を選ぶ
4. WEBパーツの鉛筆アイコン ✏ を押して設定を確かめる(`docs/LIST_SETUP.md` の「4.」)。変えたら「適用」
5. 右上の「再発行」(または「発行」)を押す

- 見出し(「行動予定表」など)は、WEBパーツの上に「テキスト」WEBパーツやセクションの見出しで付けてください(WEBパーツの中には見出しを出していません。予定表を広く見せるため)

## 5. どの版かを確かめる
- 予定表の右下に、小さく `ver 0.2.0` のように版が出ます
- アプリカタログで新しい `.sppkg` に入れ替えたのに番号が古いままのときは、ブラウザを再読み込み(Ctrl + F5)してください。
  それでも変わらないときは、数分待ってからもう一度開いてください

## 6. うまくいかないとき
| こんなとき | 考えられる原因 | 対処 |
|---|---|---|
| 「メンバーの一覧を読み込めませんでした」 | 対象者リストの名前、または列の内部名がちがう | 画面の「くわしい内容」の状態コードを見る。404 → リスト名、400 → 列名(`spConfig.ts`)。内容を Claude Code に共有 |
| 「予定を読み込めませんでした」 | 行動予定リストの名前・列名がちがう、まだ作っていない | 同上 |
| 上に黄色いお知らせが出る | 休暇・休日出勤・会社休日のリスト名か列名がちがう、または読む権限がない | WEBパーツの設定のリスト名を確かめる。直らなければ Claude Code に共有 |
| 自分の行に「あなた」が出ない/自分の予定を編集できない | WorkerNameList の M365User が空欄、またはサインインしているアカウントとちがう | M365User に本人を設定する |
| 管理者なのに、ほかの人の予定を編集できない | グループ名がちがう、グループに入っていない | WEBパーツの設定の「管理者の SharePoint グループ名」と、グループのメンバーを確かめる |
| 保存すると「権限がありません」 | リストの権限設定 | `docs/LIST_SETUP.md` の権限(一般社員は「投稿」、管理者グループは「編集」)を確かめる |
| 日付が1日ずれる | サイトのタイムゾーンが日本以外 | サイトの設定 →「地域の設定」でタイムゾーンを「大阪、札幌、東京」にする |

## 7. 新しい版を作るとき(Claude Code 向けのメモ)
- 版は3か所をそろえる:`package.json`、`package-lock.json`(先頭の2か所)、`config/package-solution.json`(solution と features の2か所。4つ目の数字は 0)
- `npm run build` → `sharepoint/solution/schedule-board-webpart.sppkg` ができる
